Read before touching `css/modal.css` or `js/modal.js`.

Digest of `README.md` §Extending and §Why you can't simplify this, which hold the full rationale and the measurements. Change one, change both.

- The plugin does two things, no more: **lock the page** behind an open menu (CSS) and **cap a tall desktop menu** so it scrolls internally (JS). Everything below is why neither is as trivial as it looks.
- Targets Ollie Menu Designer's own block classes (`wp-block-ollie-mega-menu`, `__toggle`, `__menu-container`). These are an **upstream contract**, verified against the block's `render.php`. The plugin adds no classes of its own – there is nothing to freeze, but also nothing to rename around if OllieWP changes them; a broken selector means the block changed, and the fix is to follow it.
- **Scroll lock keys off `[aria-expanded="true"]` on the toggle**, phrased as ‘a menu is open’, so it lifts the instant the last open menu closes and needs no cleanup. Locks both `html` and `body`: either can be the scroll container depending on the theme. Don't narrow it to one – it silently fails to lock on the other kind of site. **Uses `overflow: clip`, never `hidden`.** `hidden` on the root element makes it a scroll container and un-sticks a `position: sticky` header while the page is scrolled – the header, and any mega menu hung off its bottom edge, drops off-screen by the scroll amount, and the frozen page can't scroll to reach it (Ollie makes its header sticky, so this bit on `/partners/` and every other scrolled page). `clip` locks identically but establishes no scroll container. Don't ‘simplify’ it back to `hidden`, and locking the non-scroller is *not* a harmless no-op on the root – that was the bug.
- **The clamp is desktop-only by construction.** It skips a panel whose computed `position` is `fixed`, because that is Ollie's mobile overlay, which already scrolls (`overflow-y: scroll`); capping it would fight Ollie. Ollie's desktop panel is `absolute` with `overflow: visible` and no `max-height`, which is the gap this fills.
- **The clamp measures the panel's live top** (`getBoundingClientRect().top`), never Ollie's `topSpacing` default. That is what lets it compose with a transparent-header plugin that hangs the panel off the header's bottom edge: whatever the top ends up being, the cap runs from there down. Hard-code an offset and the two plugins fight.
- **The clamp is a temporary workaround.** It exists only because Ollie Menu Designer caps the panel on mobile but not on desktop; the scroll lock in `css/modal.css` stays regardless. Bug reported to OllieWP; see `README.md`. Exact removal steps and condition: `removable-workarounds.md`.
- **No cascade fight.** The scroll-lock rule outranks Ollie Menu Designer's `body:has(.menu-width-full){overflow-x:hidden}` on specificity, so the stylesheet needs no dependency and no special enqueue priority. Don't add either to ‘be safe’ – it implies an order dependency that isn't there.
- The `SETTLE_DELAY` (100ms) lets the menu finish opening before the panel is measured; Ollie animates the panel in, so measuring on the bare `aria-expanded` flip reads a mid-animation height.
